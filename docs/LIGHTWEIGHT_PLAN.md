# ATLite 轻量双模式实施计划

更新：2026-10-26。以用户最新范围为准，替代此前较大的路线图。

**目标只有一条主流程：电脑局域网发邮箱 → 手机输入 → 图色/OCR 判断页面 → 点击或滑动 → 回传邮箱和识别出的用户名。** 只支持 roothide，不做云端、账户体系、完整 AutoTouch/触动精灵兼容层、脚本商店、录制或复杂项目管理。

## 1. A/B 保留，但业务逻辑只写一份

| 模式 | 启动方式 | 提供的功能 |
|---|---|---|
| A：App 按需启动 | 打开 App、运行脚本前检查并启动引擎 | 图色、OCR、点击滑动、邮箱输入、结果回传、抖动和时间戳 |
| B：SpringBoard 桥接保活 | 小型桥接层检查、启动同一引擎；失败可降级 A | 与 A 完全相同 |

两种模式只是引擎从哪里启动、是否保活的区别，不写两套搜图/OCR/邮箱功能。用户主动停止后不自动重跑脚本。B 连续启动失败时告知原因并降级 A。

**现状必须说清：原 v0.3.10 只有 A/B 设计和探针，没有独立 daemon。本轮 v0.3.11 是修复与邮箱链路的源码开发版，仍由 SpringBoard 执行 Lua，不能标成“双模式已完成”。** 独立引擎与轻量启动器留作下一小步，先通过真机 HID、抓屏、输入和启动权限测试，再搬动功能；不为做模式开关引入额外平台。

## 2. 保留和补齐的能力

- 图色：保留取色、搜色、模板搜图；修掉颜色转换和模板采样漏检，设置计算预算。
- OCR：保留文字定位，增加返回原文的 `ocrText()`，供脚本提取邮箱、用户名。
- 点击滑动：保留多点输入基础；增加简单 `swipe()`；停止/报错时释放按住的触点和按键。
- 邮箱输入：本版 `inputText()` 只发送可打印 ASCII，覆盖普通邮箱；要求目标输入框已经获得焦点。输入事件已发出不等于目标 App 已接受，须用页面/OCR确认。
- 拟人化：保留坐标微抖和随机接触面积；修正时间戳换算，保证事件时间递增；点击按住 60–120ms。
- 局域网：只存一个当前邮箱任务，不做队列和历史后台。任务未处理完时拒绝覆盖，避免邮箱串单。

当前 ATLite 的脚本坐标仍为“点”。AutoTouch 官方 API 的像素坐标和参数不能直接混用；不为兼容历史脚本增加自动猜参数逻辑。[AutoTouch API](https://docs.autotouch.net/lua/)

## 3. 最小任务协议

1. `PUT /api/job`，JSON 为 `{"email":"demo@example.com"}`，成功返回 202、`jobId` 和 `pending` 状态。
2. 手机脚本 `getEmailJob()` 读取并认领，状态变为 `processing`。
3. 脚本点输入框、`inputText(job.email)`；按实际页面决定是否点提交。
4. `ocrText()` 返回文本块，脚本按实际页面的“用户名：”等规则提取名字。
5. `sendEmailResult(jobId,email,username,ocrLines)` 完成，或 `failEmailJob(jobId,email,reason)` 记录失败。
6. 电脑 `GET /api/result?jobId=...` 读取状态、邮箱与用户名；没有识别到名字不伪造成功。

一个新任务只能替换已完成、失败或取消的旧任务。`DELETE /api/job?jobId=...` 取消记录，**不会代替手机停止按钮**。若脚本异常结束但已经认领邮箱，引擎尽力把任务记为失败，避免无提示挂在处理中。这里只保存最近一个任务，电脑应先取回结果再发送下一封邮箱。

局域网服务延续前台 App 使用方式，目前无鉴权，适用于受信任同一局域网；本轮不新增登录、配对页面。App 后台服务是否可继续提供取决于 iOS 调度，不能许诺电脑随时访问。

## 5. 交付和使用约定

源码副本：同目录 `ATLite_v0.3.11-source/`。示例：`src/examples/email_roundtrip.at`。构建和验证状态：源码副本内 `BUILD_STATUS.md`。

具体目标 App 尚未给出，因此示例预留 5 秒手动聚焦输入框；填写 `focus`、`submit` 坐标即可适配已知页面。默认用户名规则只匹配“用户名：...”或“Username:...”，实际页面不同只修改这几行规则，不增加复杂识别平台。
