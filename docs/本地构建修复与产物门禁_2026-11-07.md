## 二、逐字节取证：官方能装 / 本地装不上，差在哪

| # | 项目 | 官方 0.3.44（Xcode macOS CI，真机可加载） | 本地 0.3.45（WSL，真机不加载） |
|---|---|---|---|
| D1 | 代码签名 | 每分片双 CodeDirectory：`slot0=SHA1` 主 + `slot4096=SHA256` 备用 | 只有单 `slot0=SHA256` |
| D2 | 链接重定位 | 两个分片都是 `LC_DYLD_CHAINED_FIXUPS`(0x34) | arm64 分片是老式 `LC_DYLD_INFO_ONLY`(0x22) |
| D3 | SDK / 链接器 | `LC_BUILD_VERSION sdk=18.5`，Xcode ld | `sdk=16.5`（另混入 18.5），老 ld |
| D4 | 包元数据 | data.tar 63 个文件**无 `./` 前缀**、属主全 `501:20`；`control.tar.gz`(GZIP) + `data.tar.lzma`(LZMA_ALONE) | 63 个文件全带 `./`、属主 `1000:1000`；`control.tar.xz` + `data.tar.xz` |
| D5 | 封号标签 | — | 0.3.45 起「封号」必须以 UTF-16LE 编进 dylib（UTF-8 搜会误判） |

补充取证：
- 官方 ar header 成员名是 `%-16s` 空格填充、**不带 `/`**：`debian-binary`、`control.tar.gz`、`data.tar.lzma`。
- 官方 `data.tar.lzma` 头是 `5d 00 00 00 04`（LZMA_ALONE，64MB dict）；Python `FORMAT_ALONE` 生成的 `5d 00 00 80 00` 同为合法格式。
- **旧版 `verify_roothide_layout.decompress()` 把 `5d 00 00 80 00` 当成 zstd magic 是错的**；zstd 真 magic 是 `28 b5 2f fd`。
- `ldid -Hsha1 -Hsha256` 可在本地产出双哈希；有 entitlements 的二进制要 `-S<ent.xml>`，无 entitlements 的 dylib 必须裸 `-S`，否则 `mmap: Invalid argument`。

## 三、能力边界（不假装修好）

- **D1 / D4 / 压缩格式**：打包层能修（重签、去前缀、改属主、对齐官方压缩格式）。
- **D2**：链接参数产物，**本地 WSL 加 `-Wl,-fixup_chains` 重编即可修好**（见第九节更正，旧结论「只有 Xcode 能修」是错的）。
- **D3**：SDK 代际差异（16.5 vs 18.5），只记录不阻断。打包层不改二进制内容。
- **静态/产物门禁永远不能代替真机加载验证**（`BUILD_STATUS.md` 既有纪律）。

### 规格更正：不做「替换官方 OCR worker」

计划书初稿 T3 曾写「替换官方 OCR worker」。逐字节取证证明这条规格本身是错的：

| | 官方 0.3.44 | 本地 0.3.45 |
|---|---|---|
| `ATLOCRWorker` 大小 / md5 | 171712 / `44331a061402890545627d8ac91f7767` | 170544 / `2016303d091171a10744f77bd04f72fe` |
| `com.apple.security.iokit-user-client-class` | 含 `H11ANEInDirectPathClient` 等 8 项 | **完全相同的 8 项** |

两包 entitlements 一致，替换没有收益；把 0.3.44 二进制塞进 0.3.45 包只会造成**版本混装**。
故剔除该动作，改为在打包时核对 ANE entitlements（`ane_problems()`），缺失则报「需重新编译」，不动任何二进制。

### 门禁判定规则

- **D0**：包内无任何 Mach-O / 结构校验失败 / ar 无法解析 → 一律拒绝放行（杜绝「空包全绿」）。
- **D1**：每分片必须 `slot0=SHA1` + `slot4096=SHA256`。
- **D2**：每分片必须有 `LC_DYLD_CHAINED_FIXUPS`。
- **D3**：SDK 代际**只记录不阻断**（`[INFO] D3 SDK=18.5` / `16.5/18.5`）。
- **D4**：`./` 前缀、属主非 501:20、ar 成员名后缀↔内容 magic 不一致、内容解不开 → 拒绝。
- **D5**：版本 >= 0.3.45 时 dylib 必须含「封号」UTF-16LE；版本解析失败按最严格处理。
- **D6**：OCR worker 缺 ANE entitlements → 报「需重新编译」。
- 结构校验复用 38 项验收器的 `macho_slices()`，两套解析器不许互相矛盾。
- 只捕获明确的解析异常；`NameError` / `TypeError` 等编程错误必须冒出来，不许伪装成 D0 让红测恒绿。

### 9.1 取证：本地 ld64-609 自带 chained fixups

| 实验 | 链接命令 | 结果 |
|---|---|---|
| 不加开关 | `ld -dylib ... mini.o` | `0x22` LC_DYLD_INFO_ONLY |
| 加开关 | `ld -dylib ... -fixup_chains mini.o` | **`0x34` LC_DYLD_CHAINED_FIXUPS** |

`~/atlite-theos/toolchain/linux/iphone/bin/ld` 二进制内含 `fixup_chains` 字符串
（ld64-609，2023 构建）。clang driver 传 `-Wl,-fixup_chains` 对 arm64 / arm64e
均生效。Theos 的 `ALL_LDFLAGS` 含 `$(ADDITIONAL_LDFLAGS)`，根 Makefile 使用
`export ADDITIONAL_LDFLAGS = -Wl,-fixup_chains` 可让 10 条链接命令全部带上开关。
